Why Tera Pilot

Trust, control, and evidence — not just generation quality

AI coding agents can edit repositories, run commands, call external tools, and finish multi-step tasks. The hard part is no longer only quality — it is trust, control, and evidence.

Trust & Control

Autonomy as a policy decision, not a label

Every layer of the agent loop is sandboxed, logged, and reversible — control and evidence by default.

🔒

Workspace sandbox

File operations are limited to the selected project root.

🛡️

Command policy

Allowed and denied commands are controlled explicitly.

🏰

OS-level sandbox

Commands run inside a Seatbelt/bubblewrap sandbox — network denied, writes kept to the workspace, secrets unreadable.

✅

Project approvals

A repository cannot silently widen its own permissions.

🎚️

Autonomy levels

always_ask · new_files_only · never_ask
Headless runs fail closed — side effects are blocked unless explicitly opted in.

👁️

Diff review

Writes can pause for human approval before they land.

🌐

SSRF-hardened web

web_fetch rejects loopback, private, and cloud-metadata hosts — DNS and every redirect hop re-checked.

🧠

Guardian

Assesses risky tool calls — approve, reject, or modify; fails closed on errors.

↩️

Checkpoints & undo

Recovery paths for every file change along the way.

📜

Activity & audit logs

Tool execution and agent identity are recorded by default.

✍️

Signed audit export

Ed25519 signatures + SHA-256 hash chaining for exported records — verify on any machine.

🗝️

Offline licensing

Pro features gate on Ed25519-signed license keys — verified entirely offline, zero telemetry, no phone-home.

These mechanisms provide control and evidence — they are not a claim of SOC 2, ISO 27001, or vulnerability-free code. See product strategy, threat model and security. Every control is covered by automated tests — 210 security/sandbox/command-policy tests plus 58 reproducible eval tasks (incl. 10 adversarial sec-*).

Install

One command, no git clone, no manual pip

Python 3.11+ is the only system prerequisite. The npm install boots an isolated virtualenv for you.

Quick start (npm)

npm install -g tera-pilot

Everything works out of the box after install:

# Web UI
tera-pilot
# Full-screen terminal UI (primary app)
tera-pilot-tui
# REST API + SSE daemon / ACP server
tera-pilot-daemon --help
tera-pilot-acp --help
# Environment doctor / signed audit
tera-pilot doctor
tera-pilot audit
# Offline license keys (optional Pro features)
tera-pilot license status

Environment knobs (optional)

VariableEffect
TERA_PILOT_PYTHONPython interpreter (default python3)
TERA_PILOT_VENVvenv location (default ~/.tera_pilot/venv)
TERA_PILOT_SKIP_PIP=1install without running pip (offline / custom)

Install from source

git clone https://github.com/ilyaosovskoi/tera-pilot.git
cd tera-pilot
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
MCP & ACP

Connect Tera Pilot to your editors and agents

Tera Pilot both consumes external MCP tools and exposes its own tools through an MCP/ACP server. Write-capable external tools should be trusted and approved deliberately.

Read-only by default

# Expose read-only Tera Pilot tools from a workspace
tera-pilot-acp --mcp-server --workspace /path/to/project

Opt into writes

# Enable writes only when you explicitly need them
tera-pilot-acp --mcp-server --workspace /path/to/project --allow-writes
FAQ

Questions, answered

Is this a replacement for Cursor autocomplete or GitHub Copilot?

No. Tera Pilot is not positioned as an autocomplete product. Its focus is controlled, private, vendor-neutral agent execution: plan, edit, run, verify and report inside a sandbox with an audit trail.

Does "local-first" mean always offline?

No. Cloud providers and remote MCP servers still send data outside the machine by design — local-first is not the same as always-offline. With Ollama or LM Studio the repository content stays on your machine.

What are the system requirements?

Python 3.11+ and a terminal. The npm install is the only prerequisite — it creates an isolated virtualenv at ~/.tera_pilot/venv automatically. Optional Rust acceleration is detected by the doctor.

How much does it cost?

Nothing for the software — MIT licensed, free to use, modify and integrate. You only pay for the model providers you choose to bring your own keys to (or nothing at all with local models). A few optional Pro features (second opinion, cost router, spend dashboard) gate on Ed25519-signed license keys issued entirely offline — verification never phones home.

Can the audit trail be verified on another machine?

Yes. Export with tera-pilot audit export, then run tera-pilot audit verify anywhere using the public key from ~/.tera_pilot/audit_key.pub. Exit code 0 means the chain is intact.

How does the OS-level sandbox work?

execute_command, run_code and auto-detected test/lint commands run inside an OS-level sandbox when a backend is available (macOS sandbox-exec/Seatbelt, Linux bubblewrap): network is denied by default, writes are restricted to the workspace and OS temp, and sensitive paths (~/.ssh, ~/.aws, ~/.gnupg) are unreadable. The mode is configurable (auto default / on / off) and on fails closed without a backend. It is a defense layer, not a full VM.

How is the security posture verified?

Security is treated as a continuously tested property: 210 security/sandbox/command-policy tests, plus a reproducible eval harness of 58 repository tasks (incl. 10 adversarial sec-* tasks). Five real vulnerabilities found by offensive testing (git alias/config-key execution, CORS origin-prefix matching, npm script aliases, …) were fixed in v2.3.4 with regression tests — see SECURITY.md and SECURITY_TEST_REPORT.md.

What about enterprise features like SSO, RBAC, compliance?

They are roadmap work. The current focus is reproducible evaluation, machine-readable evidence, transparent sandboxing, and a smooth local/BYOK onboarding path — see the product strategy.

How good are the results?

Quality depends on the selected model, provider configuration and the repository's tests. That is exactly why the runtime verifies: re-reads touched files, runs tests, and can request a reviewer before reporting.
