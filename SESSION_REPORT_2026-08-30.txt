2. Найденные и исправленные баги
--------------------------------
A. Аудит/activity-лог ложно помечал ошибки как "ok" (tera_pilot/activity_log.py)
   parse_status не знал тегов движка ([TOOL ERROR], [GIT ERROR], [MCP ERROR],
   [BLOCKED], [REFUSED], [SELF-VERIFY ERROR], [WEB_FETCH ERROR] и т.п.), а
   неизвестный префикс по умолчанию = ok. Упавшие операции в подписанном
   аудит-тракте показывались зелёными. Добавлены недостающие префиксы.
   Example: "[GIT ERROR] failed" -> 'ok' (до) -> 'error' (после).

B. sanitise_args терял данные во вложенных ключах (activity_log.py)
   Рекурсия передавала вложенный ключ вместо верхнеуровневого, из-за чего поле
   content/diff внутри вложенного dict ({"meta": {"diff": ...}}) без надобности
   схлопывалось в сводку. Теперь сводкой сжимаются только реальные payload-
   аргументы верхнего уровня; длинные вложенные строки режутся по общему лимиту.

C. Ошибочная привязка проекта в learning-loop (tera_pilot/learning_loop.py)
   Фильтр activity-лога в detect_missing_verification был по строковому префиксу
   без границы пути: /ws/proj2/... считался принадлежащим /ws/proj. Переведено
   на проверку Path.relative_to (helper _entry_path_inside).

D. Терялся финальный ответ при LFM-текстовом формате (agent_runtime/parser.py)
   Модель LM Studio (LFM 2.5) отправляет терминал как
   <|tool_call_start|>[final_answer('...')]<|tool_call_end|>, а is_final /
   parse_final_answer распознавали только JSON {"final_answer": ...}. Результат —
   пустой final_output ("no content returned"). Добавлено распознавание LFM-
   текстового terminal + подавление ложного предупреждения "[parser] Tool name
   lookup failed: 'final_answer'".
