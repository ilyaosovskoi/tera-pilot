## Failure analysis by root cause

### 1. Harness: parallel launches collide on a single agent (3 runs, 19:58)

`add-clamp-function`, `add-multiply-function` and `refactor-enum-constants`
were launched within ~2 seconds of each other against one server. The server
accepts one agent request at a time, so three runs aborted immediately with
`Another agent request is already running` (0 iterations, ~0.02 s each). These
are **invalid runs**, not agent failures.

**Fix shipped (same day):** `eval/runner.py` now retries the stream with a
short backoff (3 attempts) when the server reports `already running` with 0
iterations, so accidentally parallel launches serialize instead of failing
(see `test_api_driver_retries_parallel_collision`).

### 2. Harness: `error` overrides a passing fix (refactor-enum-constants, 20:02)

The agent produced a working solution — `test_passed: true`, exit code 0,
`verification_status: passed` — but the **final** LLM response failed with
`LM Studio HTTP 400: Invalid diff …` and the SSE stream ended with an `error`
event. `eval/runner.py` gives the driver's `error` status priority over the
test result, so a genuinely solved task is reported as failed.

**Fix shipped (same day):** `build_result()` now reports `success` when the
verification tests passed and the agent actually ran (iterations > 0), even if
the driver ended on a terminal `error`; a run that never started (0 iterations,
e.g. a collision) stays `error` (see `test_build_result_error_does_not_mask_passing_tests`).

### 3. Provider: empty model responses (3 runs)

`repair-test-float-tolerance` (19:26, 19:42) → `[tool_calls] no content
returned`; `repair-test-import-path` (19:09) → `[length] no content returned`.
LM Studio signaled `finish_reason=tool_calls`/`length` with empty content.
The runtime retries with a corrective reminder (already shipped), but the runs
still burned out. These are provider instability, not task difficulty.

### 4. Agent: stops after 5 read-only iterations without editing (5 runs)

Pattern: exactly 5 iterations of `read_file`/`glob`, then the run ends with no
`str_replace`/`write_file` at all:
fix-missing-return (13:51), fix-config-loader (13:57), add-word-count (14:28),
fix-typo-variable (14:30), repair-test-float-tolerance (19:12). The model ends
its turn without attempting a fix — a small-model behavior worth a prompt
nudge ("you must modify at least one file").

### 5. Agent: partial fix on fix-config-loader-empty-file (7 of 8 runs)

The task needs **two** cases handled: empty file **and** missing file
(`FileNotFoundError`). The agent consistently fixes only the empty-file case;
the test suite stays at `..F` (missing-file case red). One run (19:39) even
reported *"The tests are passing"* while the suite was still failing — a
verification hallucination. This task is the clearest prompt-improvement
candidate: state both required cases explicitly.
