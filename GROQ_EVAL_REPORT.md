## 3. Плюсы текущего прогона

- **Агент работает корректно на реальных задачах**: читает файлы, делает точечные правки через `str_replace` (не переписывает файл целиком), завершает задачу текстовым ответом.
- **Правильные правки**: `return discounted` в `apply_discount`, реализация `word_count`, починка пустого/отсутствующего конфига, `multiply(a, b)` + тесты — всё прошло проверку `pytest`.
- **Механизм retry устойчив к rate-limit**: 429/413 обрабатываются с экспоненциальным бэкоффом, прогоны дожимаются до конца, даже когда TPM почти исчерпан.
- **Секьюрити-политика работает**: попытка агента выполнить `python -m pytest` заблокирована; команды вне вайтлиста не выполняются.
- **Инфраструктура eval-харнеса в порядке**: baseline/финальные тесты, schema-валидация, отчёты (`eval.runner report`).
- **Бенчмарки в норме** (локальные, без API): hot paths — native 1.7–43.5×, security-проверки 0.03–33 µs/оп.

## 4. Найденные проблемы и исправления (в этом цикле)

1. **Несовместимость native-tool-calling моделей с legacy-циклом** (gpt-oss-120b → HTTP 400 «tool choice is none»).
   → **Исправлено:** цикл агента теперь передаёт провайдеру native tool schemas (`build_native_tools_schema()`, OpenAI function format, секционная фильтрация как в `TOOL_SCHEMA`). Native `tool_calls` сериализуются в текст `{"tool":..., "args":...}`, который понимает `OutputParser` — работают и text-JSON модели (qwen), и native (gpt-oss).
2. **Агент не мог сам запускать тесты**: `python -m pytest` / `python3 -m pytest` блокировались политикой (`-m` = опасный флаг).
   → **Исправлено:** `python[3] -m pytest` разрешён (точечный allowlist модуля); `python3 -m pip install`, `-m venv`, `-m http.server`, `-c` и т.п. остаются заблокированными.
3. **Неинформативный ответ при блокировке команды** — агент упорно повторял одну и ту же заблокированную команду, сжигая итерации.
   → **Исправлено:** `execute_command` возвращает причину блокировки + подсказку («use the bare `pytest` binary»), плюс в `TOOL_SCHEMA` добавлена подсказка про `pytest`.
4. **Устаревшая модель в конфиге** → заменена на рабочую (`qwen/qwen3.6-27b`).
5. **Ограничение free-тира Groq (не баг, но важно знать):** 8000 TPM / 200k TPD. Запрос агента ~5.7–7k токенов (системный промпт 5.3k + схемы ~1.6k) → ~40 c на запрос с retry; ~200k токенов хватает на несколько задач в день. HTTP/GUI-путь шлёт ещё больший промпт (MCP-каталог, pinned-файлы) — с free-ключом он может упираться в лимит одного запроса (413).

## 5. Как воспроизвести

```bash
# 1) ключ и модель в ~/.tera_pilot/config.json:
#    providers.groq.api_key = gsk_...
#    providers.groq.model  = qwen/qwen3.6-27b  (или openai/gpt-oss-120b)
# 2) прямой прогон eval-задачи (драйвер direct_groq, без HTTP-сервера)
python3 /tmp/eval_drive_groq.py fix-missing-return
# 3) сводка по результатам
python3 -m eval.runner report --dir eval/results
# 4) бенчмарки
python3 benchmarks/bench_hot_paths.py
python3 benchmarks/bench_security.py
```

> Примечание: для повторного полного прогона дождитесь сброса дневного лимита Groq (200k TPD, сброс ~00:00 UTC) либо поднимите лимит в консоли Groq.
